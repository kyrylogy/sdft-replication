# Results index

Where each reported number lives, which script writes it, and how to rebuild it.
Summary of the findings: [results page](https://kyrylogy.github.io/sdft-replication/). Every result in
readable tables, by arm, stage and seed: [analysis/SUMMARY.md](analysis/SUMMARY.md).

## Folders

| Folder | Contents | Written by |
|---|---|---|
| `analysis/` | `SUMMARY.md` (all results, readable), result tables (CSV), `final_stats.txt`, `adapter_distance.csv`, `figures/`, `provenance/` | `make_summary.py`, `collect_results.py`, `stats_final.py`, `adapter_distance.py`, `make_figures.py`; `provenance/` by `battery_audit.py` and `away_final.sh` |
| `runs_export/` | per-run records: run stamps, per-item scores of every eval, lm-eval outputs, final-checkpoint generations | `export_runs.py` (a scrubbed copy of `runs/`, which also holds the weights and is not committed) |
| `wandb_export/` | training curves (downsampled) and per-run summaries/configs | `export_wandb.py` |
| `docs/` | results page (GitHub Pages); `docs/figures/` are copies of two files in `analysis/figures/` | by hand |

## Rebuild

From the committed records (CPU, a couple of minutes; needs `pyyaml`, plus `pandas` and `matplotlib` for figures):

```bash
python collect_results.py --root runs_export --out analysis   # all CSV tables
python stats_final.py     --root runs_export --out analysis   # final_stats.txt
python make_figures.py                                         # analysis/figures/
python make_summary.py                                         # analysis/SUMMARY.md
```

Rebuilt this way, every table and `final_stats.txt` match the committed files except `runs_index.csv`, whose
`has_adapter` is false because no weights are exported. `adapter_distance.csv` and
`provenance/battery_audit.txt` need the weights and the full `runs/`, so they are rebuilt only on the
training host.

On the training host, refresh everything after new runs with:

```bash
python collect_results.py && python stats_final.py
rm -f analysis/figures/fig_scale_trend.* && python make_figures.py   # scale trend is skipped at one scale
python make_summary.py
python adapter_distance.py --glob 'runs/*/checkpoint-*' --csv analysis/adapter_distance.csv
python battery_audit.py > analysis/provenance/battery_audit.txt
rm -rf runs_export && python export_runs.py                       # --responses none|final|all
python export_wandb.py --clean-index                              # or a fresh python export_wandb.py
cp analysis/figures/fig_retention_endpoints.png analysis/figures/fig_forgetting_bars.png docs/figures/
```

The numbers on the results page are typed in from the tables below, so update them by hand after a rebuild.

## Not produced by a committed script

These were computed by hand from the files above:

- Holm-corrected battery p-values (5.6): two-sided z = seed mean of (adapted − base, from `forgetting.csv`'s 4-dp columns) ÷ seed mean of √(base_stderr² + adapted_stderr²), i.e. one run's standard error, then Holm over the six tasks within each arm. Per-prompt lm-eval samples were not saved, so a paired test is not possible.
- Fisher tests on pooled forgotten/gained counts (5.2, 5.3).
- The unpaired seed-blocked permutation test (p = 0.148 one-sided). `final_stats.txt` has the paired version (p = 0.2964 two-sided).
- Paired t-test over seeds (A.6), the post-hoc power estimate (A.7), and the recomputation without the three holdout items that duplicate training prompts (A.4).

## Known quirks

- Tables written before the acq50 fix in `collect_results.py` label the acq50 runs `arm_id = sft`: their `aggregate.csv` "sft" rows average six runs, `significance.csv` lacks the 15 SFT vs SFT-acq50 pairs, and `method_effect.csv` used plain SFT only because of directory sort order. Rebuild with the current script.
- `aggregate.csv` `std_acc` is the population standard deviation (ddof = 0).
- `forgetting.csv` has no stage column: join it with `runs_index.csv` on the run name (the figure and `SUMMARY.md` do).
- `wandb_export/` also holds the earlier 3B pilot (`*3b*`, July 2026; not used). The 7B configs trained before 2026-08-16 have three W&B runs each, because a driver bug executed every config three times; the evaluated adapter is from the last execution. The later SFT-acq50 and joint runs ran once. `<run>__eval` entries are evaluation jobs and hold only accuracies.
- `git_dirty: true` is recorded for the training of every seed-1234 and seed-2024 run, the three acq50 stage-2 runs and the anchor run `sft_lora_7b_tooluse_s1`, and for every lm-eval battery and every stage-2 eval stamp. `analysis/provenance/dirty_diff.patch` (`git diff bc810cbe -- eval_runner.py run_tier.sh`, taken 2026-08-25) shows the harness changes behind the `bc810cbe` runs; for stamps at later commits those files were already committed, and what made the tree dirty was not recorded.

## Citing a fixed version

Tag the commit the thesis numbers come from and link files through the tag, so links keep pointing at those exact numbers:

```bash
git tag thesis-freeze-YYYYMMDD && git push origin thesis-freeze-YYYYMMDD
# https://github.com/kyrylogy/sdft-replication/blob/thesis-freeze-YYYYMMDD/analysis/final_stats.txt
```
